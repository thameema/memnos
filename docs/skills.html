Skills

Curated skills, one install at a time.

Tommy ships no copies of anyone else’s skills. The memnos marketplace pins upstream Claude Code plugins to a commit and groups them into opt-in bundles — install one, measure whether it actually fires, drop what doesn’t.

$ tommy skills install all
Read the full reference →
How it works

Pinned, not vendored

Every bundle is a Claude Code plugin whose dependencies point at upstream plugins — pinned to a commit SHA via git-subdir sources in the memnos marketplace. Nothing is copied into this repo, so credit, licence and updates stay with the original author.

Install a bundle

One command adds the memnos marketplace (if needed) and installs the plugin. Restart the Claude Code session, or run /reload-plugins, to load the new skills.

Measure, don’t guess

tommy skills stats and eval read your own Claude Code transcripts — uses, tool errors, your corrections — per installed skill, so you decide what to keep from evidence, not a guess.

Mind the budget

Claude Code lists every installed skill's name and description each turn inside a fixed context budget (skillListingBudgetFraction, default 1%). Install only what you’ll use, or raise the budget in settings.json.

The bundles

Install one, several, or all — every bundle below plus memnos memory, in one plugin.

tommy skills installPluginWhat’s inside
alltommy-allEverything below, plus memnos memory, in one install.
coretommymemnos memory only — no skill bundles.

architecttommy-architectC4 documentation and multi-perspective design review (comprehensive-review, c4-architecture; wshobson/agents, MIT).
reviewtommy-reviewDifferential security review, context building, variant analysis (trailofbits/skills, CC-BY-SA-4.0).
securitytommy-securitySharp-edges, supply-chain, agentic-actions and static-analysis audits (trailofbits/skills, CC-BY-SA-4.0; static-analysis needs semgrep installed).
design-reviewtommy-design-reviewTommy-authored HLD and LLD reviewers that check a design against the real code.
qatommy-qaTommy-authored frontend, backend and REST API QA — for apps you own and test environments only.
explaintommy-explainTommy-authored: explains code, bugs and findings in plain English with a real-world scenario.
pentesttommy-pentest25-skill penetration-testing pack: an ROE/authorization + scope gate runs first (and can’t itself run curl/wget/nmap/sqlmap/nikto), then header/TLS/CORS/secret/dependency/code scans and OWASP Top 10-mapped reporting (jeremylongshore/claude-code-plugins-plus-skills, MIT). Not included in all.

tommy-pentest is deliberately excluded from all — pentest is a different risk class from the other bundles, so it stays a separate, explicit install.

Reference

tommy skills …

# install a bundle through Claude Code (adds the memnos marketplace first if needed)
tommy skills install all

# curated plugins: upstream repo, pinned commit, licence, installed?
tommy skills list

# which installed skills actually fire, from your own session transcripts
tommy skills stats

# productivity scorecard per skill: uses, edits/commands after, tool errors, your corrections, verdict
tommy skills eval

# read-only look at an upstream repo before adding it: licence, hooks, scripts, risky exec/network patterns
tommy skills vet owner/repo

# offline: would a keyword hint put the right installed skill in the top 3? no model calls, free
tommy skills bench prompts.jsonl

# maintainers only: where upstream has moved past each pin
tommy skills update

eval reads proxies, not quality — a skill can fire often and help little, or fire rarely and matter. The verdict is a prompt to look, never a grade and never a reason to delete on its own. Full command reference, including update --apply, is in the Tommy README.
