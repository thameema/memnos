The one concept worth knowing

Namespaces — separate notebooks for separate things

A namespace is just a labeled place memories go — think of it as a dedicated notebook. A “work” notebook and a “personal” notebook never bleed into each other unless you want them to.

work:acme-project
  • Client decisions
  • Deadlines
  • Who’s who
personal
  • Preferences
  • Ongoing tasks
  • Family notes
+ one per project
  • Add more any time
  • Only as needed

Most people start with just one namespace and only add a second once they notice they actually want one.

Setup · Windows

Installing on Windows

This installs memnos locally — no cloud account, no Docker, nothing else to set up first. Four commands, run in PowerShell.

1

Install uv (a Python package runner)

# run in PowerShell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
2

Open a new PowerShell window, then install memnos

uv tool install memnos
memnos --help          # confirms it installed
3

Set it up

Downloads its own private database automatically — nothing else to install first.

memnos setup

This prints a one-time admin token — save it somewhere safe.

4

Start it, and connect it to Claude Code

memnos start
memnos agent-setup claude-code

Restart Claude Code once afterward. From then on, recall and save happen automatically in the background.

That's the whole install. For the full step-by-step with troubleshooting (antivirus scan delays, port conflicts), see the Windows guide.

The honest questions

Privacy & cost

Is my data private?

Yes. Everything lives in a database on your own machine. Nothing is sent anywhere unless you explicitly add a cloud AI key.

Does this cost anything?

No — no subscription, no usage fee. An optional OpenAI key sharpens recall slightly; it's entirely your choice, and skippable.

What if I use more than one AI tool?

memnos connects to Claude Code, Claude Desktop, Cursor, Windsurf, and anything else that speaks MCP — one memory, shared across all of them.
